# Research protocol

Every change should answer a falsifiable question.

1. Record hypothesis, task definition, baseline, seed, evaluation and compute budget in an issue.
2. Keep experimental code, raw results and configuration linked to each other.
3. Clearly distinguish measurements, hypotheses and untested claims.
4. Preserve negative results and use matched seed/task sequences for comparisons.
5. Add an offline smoke test for new experiment code. Do not download datasets in CI.
6. Never commit private/company measurements, credentials, proprietary models or unauthorized datasets.

States: **verified** (raw data can be checked), **reported** (only a report is available), **planned** (not run).
